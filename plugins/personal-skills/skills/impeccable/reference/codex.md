# Generated Visual Direction And Assets

Read when the task calls for generated mockups, visual exploration, or raster
assets. Follow the available image-generation tool and skill instructions;
this reference defines the design handoff, not a second generation runtime.

## Choose The Exploration Depth

Use the brief and supplied palette, atmosphere, and references. Ask only about
unresolved choices that materially affect the result. A palette artifact is
useful when color is the decision; mockups are useful when composition is the
decision. Neither is a universal prerequisite for code.

For a user-requested studio workflow, show the proposed palette and/or mock
alternatives at the checkpoints they requested, and wait for their selection.
When the user delegates the choice, select the strongest direction against the
brief and continue. Existing approval carries forward; do not demand it again.

Generate enough alternatives to compare meaningful structural choices. Keep
accepted identity consistent while exploring hierarchy, density, or composition.
For long pages, show enough beyond the hero to establish the wider system.

## Translate A Direction Into Implementation

Inventory the major ingredients of the chosen direction: composition, imagery,
section sequence, typography, navigation, controls, and distinctive motifs.
Choose an implementation for each: semantic HTML/CSS, SVG, an existing icon
set, canvas, sourced imagery, or generated raster.

Keep UI text, controls, charts, and layout chrome in code when that preserves
semantics and clarity. Preserve essential imagery and silhouette rather than
silently replacing them with generic decorative panels. Explain material
implementation deviations from an accepted mock.

## Produce Reusable Assets

Use generation or editing for assets that need it. A small crop from a full-page
mock is a reference, not automatically a production-quality asset. Produce at
appropriate resolution and verify crop, transparency, visual fidelity, and
absence of unwanted text or presentation chrome.

Produce assets in the current task by default. When delegation is authorized
and useful, use an available asset-production agent with the reference, output
directory, dimensions, format, transparency needs, and what code will own.
Do not require a particular role or request agents merely because an agent
configuration is bundled.

Keep task source crops separate from final consumed assets. Return a compact
manifest of produced files and semantic implementation notes where needed.
Inspect the assets in the actual page before declaring fidelity complete.

Return to [craft.md](craft.md) to implement and verify the direction.
