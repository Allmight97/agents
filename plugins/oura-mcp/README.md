# Oura MCP

Private, single-user, read-only access to Oura API v2 through modern Streamable HTTP.
The deployed service exposes exactly two MCP tools:

- `oura_catalog` describes every documented collection, its query shape, and unresolved gaps.
- `oura_query` retrieves one bounded collection while preserving the native Oura response and provenance.

The service does not summarize, score, coach, diagnose, or durably store health responses. Auth0
authorizes calls from ChatGPT or another harness; a separate Oura OAuth credential authorizes the
service to retrieve the owner's Oura data.

## Architecture

```text
ChatGPT web -- Auth0 access token --> POST /mcp
                                         |
                                         +-- oura_catalog
                                         +-- oura_query -- Oura OAuth token --> Oura API v2
```

The hostname is deployment configuration. `/mcp` is the stable public protocol path. There is no
stdio entry point, GET event stream, protocol session layer, local production bridge, data
warehouse, or ordinary response cache.

## Local contract checks

Python 3.10 or newer and `uv` are required:

```bash
uv sync --dev
uv run pytest
uv run ruff check .
```

To run the synthetic backend locally, copy `.env.example` values into your shell and use a real
Auth0 development tenant. `MCP_PUBLIC_BASE_URL` may be `http://127.0.0.1:8000` for loopback-only
testing. Then run:

```bash
uv run oura-mcp serve
```

The MCP endpoint is `POST /mcp`. `GET /healthz` is the only operational endpoint. OAuth protected
resource metadata is generated by the MCP SDK from `MCP_PUBLIC_BASE_URL`.

## Move from fixtures to live Oura

1. Mount durable storage at `/var/lib/oura-mcp`.
2. Set `OURA_BACKEND=live` and every `OURA_*` variable in `.env.example` through the host's encrypted
   secret store. Do not commit or paste those values into issues, logs, fixtures, or agent prompts.
3. Generate a Fernet key for `OURA_TOKEN_ENCRYPTION_KEY` and a separate random value of at least 32
   bytes for `OURA_STATE_SECRET`:

   ```bash
   uv run python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
   uv run python -c 'import secrets; print(secrets.token_urlsafe(48))'
   ```

4. Register the exact deployed `OURA_REDIRECT_URI` in Oura.
5. In the deployed service shell, run `oura-mcp authorization-url`. Open the short-lived URL and
   approve access. The public callback validates signed state, exchanges the code, and writes only
   the encrypted rotating credential to the durable volume.

`OURA_SCOPES` defaults nowhere in production. Supply the scopes granted to the Oura application.
The example lists Oura's publicly documented core scope names; dashboard-only scope labels must be
confirmed through the live authorization response rather than guessed in source code.

## Required Auth0 contract

Create an Auth0 API whose audience exactly matches `AUTH0_AUDIENCE`, allow the `oura:read` scope, and
set `AUTH0_ISSUER` to the tenant issuer. The service:

- publishes RFC 9728 protected-resource metadata;
- advertises Auth0 as its authorization server;
- returns a `WWW-Authenticate` discovery challenge for unauthenticated MCP requests;
- verifies signature, issuer, audience, expiry, and scope on every MCP request.

## Container

Build and run the provider-independent image from this directory:

```bash
docker build -t oura-mcp .
docker run --rm -p 8000:8000 --env-file .env -v oura-mcp-data:/var/lib/oura-mcp oura-mcp
```

The deployment platform must provide public HTTPS, a persistent volume for the encrypted Oura
credential, encrypted environment variables, and an HTTP health check at `/healthz`.

The repository includes a root `render.yaml` as the initial managed-host deployment. Render is used
because one Blueprint can build the existing Dockerfile, expose public HTTPS, gate automatic deploys
on CI, attach the credential volume, generate both encryption secrets, and prompt for account-bound
values without committing them. The `oura-mcp` Render service name is operational and may be renamed;
it is not the plugin's permanent user-facing name.

Set `MCP_ALLOWED_HOSTS` to every hostname that can legitimately reach the service, including the
Render-generated hostname and any custom hostname. Set `MCP_PUBLIC_BASE_URL` to the one canonical
origin that Auth0 and ChatGPT should use as the resource identifier.
