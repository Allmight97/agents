# Comparison Workspace

Use this shape when the reader must compare two or more complete outputs across
one or more subjects, branches, models, designs, plans, or states. It is a
revisitable inspection surface, not a dashboard and not a decorative gallery.

## Interaction Model

- Keep **candidate** as the baseline control axis. Add a separate **subject**
  axis only when the workspace contains several subjects.
- Open in an equal side-by-side view; when several subjects exist, show the
  same selected subject in every frame.
- Let the reader switch to one candidate at full workspace width without losing
  the selected subject when that axis exists.
- Give every candidate an **Open full** path. Keep it same-origin in a hosted
  workspace so one authentication covers the comparison and full output.
- Preserve each candidate's own visual language inside a neutral wrapper.
- Label candidates and subjects literally. Reveal model or author identity when
  the comparison is not blind.
- Stack frames on narrow screens. Keep controls keyboard-accessible and visible
  above the comparison.

Build a local comparison page unless the user requested hosting or the approved
workflow already includes it. For a hosted comparison, prefer one private site
with routes, tabs, or embedded same-origin artifacts when separate sites would
create repeated authentication or navigation. Reuse and version that workspace
for later rounds rather than accumulating one site per candidate.

## Information Design

The wrapper should carry only comparison context:

- what is being compared;
- which subject is active when there are several, and which view is active;
- candidate identity;
- how to open the complete output;
- the criteria the reader should notice, when those criteria are not already
  obvious from the task.

Use equal frame dimensions, restrained typography, hard alignment, and minimal
ornament so the wrapper does not compete with or favor a candidate. Avoid
summarizing each candidate above its frame; let the output remain the evidence.

## Selection Gate

Use this workspace when at least one is true:

- full outputs need direct visual inspection rather than extracted metrics;
- the same candidates must be compared across several subjects;
- the reader needs side-by-side, focused, and full-page views;
- the comparison will receive additional rounds or human judgments;
- one authenticated host materially reduces access friction.

Use a table or ordinary page when stable fields can be compared without opening
the underlying outputs. The workspace earns its keep by eliminating context
switching and repeated reconstruction.

## Living Reference

When accessible, the private
[Presentation Artifact Skill Bench](https://presentation-artifact-bench.jstarprime.chatgpt.site)
is an optional living example: subject switcher, side-by-side default,
single-candidate focus, equal embedded frames, and same-host full output. The
instructions above are complete without access to it. Treat its mechanics as a
reference, not its styling or copy as a template.
